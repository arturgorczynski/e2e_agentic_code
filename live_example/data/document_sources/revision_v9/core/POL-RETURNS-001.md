# Commercial return window

## Purpose and applicability

This policy sets the review window for an Acme Wholesale business customer's
request to return delivered goods. It applies to the order lines identified in
the request and to the policy version in force on the relevant delivery date.
The window is **{{WINDOW_DAYS}} calendar days** from recorded delivery. A request
inside the window is eligible for review; it is not an automatic acceptance,
credit or refund.

## Request and evidence

Customer Support records the account and order IDs, the affected product and
quantity, the customer's reason, and the date the request was received. The
reviewer checks the delivery confirmation for each affected consignment. A
dispatch date by itself does not establish delivery. If no delivery date is
recorded, Support requests the missing carrier or customer evidence and leaves
the window assessment open rather than assigning an estimated date. For damage
or shortage, attach the ticket reference and the available photographs, packing
record or shipment-line comparison.

## Decision and handoff

Support compares the request date with the verified delivery date using the
applicable version of this policy. It records the calculation, the supporting
shipment IDs and any uncertainty. Warehouse staff separately confirm whether
goods were received back and record their condition and quantities. Finance
reviews any proposed credit against the posted invoice. A credit note reduces
an amount owed; a cash refund requires a separate authorized payment process.
Neither is evidence that physical goods were returned.

Requests outside the ordinary window, disputed delivery dates and damaged-goods
claims go to the owning team for a documented decision. Support must not promise
compensation or change stock or finance records while those reviews are pending.

## Version record

The effective interval and version number in the document register determine
which return window applies. Preserve earlier versions for historical cases and
cite the version used in the case note. A later version does not change a case
whose relevant event occurred under an earlier version.
