# Report review, approval and retention

## Scope

An employee may prepare a report from records and documents within their
assigned business scope. The employee who starts the conversation owns its
draft and saved output. A report may summarize facts and calculations, but it
must not turn an uncertain explanation into an established finding.

## Proposal for review

Before saving, show the owner the exact proposed title, body, source record and
document IDs, document versions, business reference date and operation ID.
Separate observed facts, calculations, assumptions and recommendations. A
request to prepare a draft is not an instruction to save it. The owner may
approve, edit and approve, or reject. An edited proposal receives the same
content and access checks as the original.

## Save and audit

At the decision point, recheck identity, scope and the cited source versions.
If material evidence has changed, return an updated proposal for review. One
operation ID identifies one intended save; a retry or restart must return the
existing outcome rather than create duplicate files. Record the proposal,
decision, attempted write and completed write as distinct events. Rejection
does not create a report artifact. A displayed confirmation must be backed by
the completed save record.

## Distribution

An export checks ownership and permissions again. Possession of a report ID or
download path does not authorize another employee to read it. The portal saves
reports locally; sending one to a customer or colleague requires a separate
business action. Label reports about 2011 source history and contemporary
fictional records separately, including their reference dates and provenance.
