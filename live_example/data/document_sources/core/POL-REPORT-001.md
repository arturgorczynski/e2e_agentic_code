# Review and save a report

Reports belong to the employee who owns the conversation. Before a save, show a concrete
proposal containing its title, body, source record/document IDs, source versions,
business reference date and operation ID. A request to draft is not approval to save.
Do not claim the report exists while the operation is still pending.

## Decisions

The owner may approve, edit and approve, or reject. Edited content must pass the same
validation as the original proposal. On resume, recheck ownership, permissions, arguments
and source versions. If the authorized evidence changed, return a revised proposal for
review instead of saving a stale statement. Rejecting the proposal creates no saved
report artifact or report database record.

The operation ID identifies one intended save. Repeated submissions or a restart must
return the same outcome instead of producing duplicate files. Preserve enough audit
evidence to distinguish a proposal, a decision, an attempted write and a completed write.
The visible assistant answer is not proof that the final write occurred.

## Access and content

A report must not expose source data that its owner is not permitted to read. A title
edit cannot grant finance access. Exports check ownership again; knowing a file or
report identifier grants no access. State assumptions and unknown causes directly.
The first release saves reports locally and does not send them to customers or coworkers.
